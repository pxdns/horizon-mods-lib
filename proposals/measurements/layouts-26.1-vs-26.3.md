# Packet layouts: Horizon's 26.3 decoders against 26.1

Generated by `tools/measure/layout_diff.py`. Horizon's decoders (`crates/horizon-protocol/src/packets`, read as text) are compared with minecraft-data's 26.1 (protocol 775) layouts, matched packet by packet through Mojang's packet ids for 26.1. A layout is reduced to the kinds of its top-level fields; equal kinds can still hide a changed meaning, and a difference can be only the two sources describing a type differently. Treat the list as the packets to read by hand, not as a verdict.

- Compared: 158 packets modelled by Horizon with a 26.1 packet of the same name.
- Same field kinds: 137.
- Different number or kinds of fields (review): 21.
- Only a nested type against a plain one (the sources describe it differently; read by hand): 17.
- Written by hand in Horizon (not read here): 12.
- Not modelled by Horizon (decoded as `Unknown`): 3.
- Modelled by Horizon, no packet of that name in 26.1 (new in 26.2 or 26.3, or renamed): 25.

## What reading the decoders showed

I read the Horizon decoders for the packets below, not only the generated kinds.

**Real wire differences between 26.1 and Horizon's 26.3**

- **`accept_teleportation` (serverbound).** 26.1 sends the teleport id only. Horizon's `AcceptTeleportation` sends the id plus `x, y, z`
  (three doubles) and `yaw, pitch` (two floats). A translator going to an older server has to drop the five extra fields.
- **`login_finished` (clientbound).** Horizon reads the profile (uuid, name, properties) and then a second UUID, `session`. A
  1.21.11 server does not send it, so a translator has to supply one. What Horizon uses it for was not read here.
- **New packets** (names only in 26.3, from the id comparison): Horizon models `attack` (`id`), `punch` (empty), `set_game_rule`
  (a list of rule name and value) and `spectator_action` is *not* modelled; clientbound, it models `swing_animation` (`id`, `hand`,
  `kind`, `duration`) and `game_rule_values` (a list of rule name and value), and does **not** model `add_transient_block`,
  `low_disk_space_warning` or `post_effects`. Unmodelled packets arrive as `Unknown` and are skipped, so a translator does not
  need to produce them.

**False alarms of the first pass, now fixed**: `Ping`, `Disconnect` and `LoginFinished`-style names are reused by several states in
Horizon (`status::Ping` against `configuration::Ping`); the script now picks the struct from the state's own file. Configuration
`Ping` is `{ id: i32 }` and its `Disconnect` is an NBT component, the same as 26.1.

**Listed above, probably only different grouping** (Horizon wraps fields in a helper type, minecraft-data lists them flat):
`entity_position_sync`, `level_chunk_with_light`, `light_update`, `login`, `player_chat`, `chat`, `chat_command_signed`,
`container_click`, `sign_update`, `use_item`, `use_item_on`, `section_blocks_update`, `forget_level_chunk`,
`set_default_spawn_position`, `map_item_data`, `player_look_at`, `damage_event`, `disguised_chat`, `set_score`. For each, the two
field lists in the section above have the same fields in the same order once the helper types are expanded, but **I did not check
every helper's inner layout**, so these stay on the review list until a translator's tests (replaying real 1.21.11 traffic) say otherwise.

**Together with 774 -> 775** (from the earlier minecraft-data diff): `update_time`, `advancements`, `open_book`, `use_entity`,
`arm_animation`, `block_place`, `use_item`, `client_command`, `chat_command_signed` and `enchant_item` changed layout between
1.21.11 and 26.1. The hand-written codecs and the packets Horizon does not model (listed above) are not covered by either
comparison.

## What this changes in the estimate

The packet layouts are less work than the id and registry tables suggested: of 158 packets compared, 137 have the same field
kinds and only a handful of real differences were confirmed (two layout changes and the new packets). Chunk data, light data,
item components and entity metadata are inside nested helper types and hand-written codecs, and those are where the layout work
of a translator will be; this pass says nothing about them. The next measurement is those four formats, read from the decoders in
`crates/horizon-protocol/src/chunk.rs`, `item.rs` and `entity_data.rs`.
