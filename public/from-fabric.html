    Porting

    From Fabric to Horizon, one behaviour at a time.

    The Tempest project has a matrix of 186 Fabric mods across five game versions. This is what happens when you take that list to a game written in Rust.

    Start with the list

    Horizon implements Minecraft 26.3, so the first filter is blunt: 34 of the 186 mods have no 26.3 build and are out. Of the remaining 152, most are libraries, performance mods a native engine does not need, or packs. What is left is a short list of mods that are about what you see and press.

    Rule one: copy the behaviour, never the code

    Upstream mods are LGPL, GPL, MIT, all-rights-reserved. A port that contains none of their code owes them credit and nothing else, and it owes the reader an honest account of what it does. So each port starts from using the original, writing down what it does, and writing Rust. The credits name every original and its licence.

    Rule two: the logic gets tests

    Zoomify's wheel clamps between 1.25x and 16x. A test fails if it does not. Waypoints compute a vanilla yaw to a block; one test pins north, south, east and west. The hook helpers cannot be tested without the game, so they are kept to a few lines, and CI type-checks them against the real Horizon.

    Rule three: say what is missing

    Xaero's minimap is only partly ported: Horizon ships its own minimap, and there is no map-screen hook, so what is left is the waypoints idea. The catalogue says so.

    A port, end to end

    Zoomify holds a key and zooms. On Horizon that is three hooks. The key hook is this much code:

    // The zoom key went down or up: the player's own choice of key.
fn zoomify_key(game: &mut crate::game::Game<'_>, key: &str, pressed: bool) {
    use crate::game::lib_zoomify as m;
    // Turned off in Options > Mods: nothing until the next build leaves it out.
    if !game.native_on(m::ID) {
        return;
    }
    if key != game.native_mod_key(m::ID, m::KEY, m::DEFAULT_KEY) {
        return;
    }
    let playing = game.native_playing();
    let game = &*game;
    m::key(playing, pressed, |name| game.native_setting(m::ID, name));
}

    And the wheel claims its steps while the zoom is on, so the hotbar does not move:

    // While the zoom is on, the wheel changes it instead of moving the hotbar.
fn zoomify_wheel(game: &crate::game::Game<'_>, steps: f32, claimed: &mut bool) {
    use crate::game::lib_zoomify as m;
    if game.native_on(m::ID) && m::wheel(steps) {
        *claimed = true;
    }
}

    Everything else (the levels, the easing flag, the turn scaling, the settings buttons) lives in runtime.rs and has seven tests.
